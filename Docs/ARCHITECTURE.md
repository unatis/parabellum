# Карта проекта: код, данные, проверки

Где что лежит и почему именно там. Решения и их причины — в [CLAUDE.md](../CLAUDE.md),
способ построения моделей — в [METHOD.md](METHOD.md).

## Принципы, из которых следует всё остальное

**Модель оружия — это данные, не код.** Патроны, оружие, материалы, эталонные таблицы лежат
в `Content/Data/*.csv`. Текстом, а не в `.uasset`: правки видны в diff, загружаются на старте,
и правит их кто угодно без редактора.

**Ассеты порождаются скриптами.** `.uasset` — двоичный формат, агентом не редактируется.
Всё в `Content/` получено скриптами из `Tools/`; уровень, материалы, ассеты ввода — тоже.
Руками в редакторе уровень не править: следующий прогон генератора затрёт правки.

**Сеть с первого дня, игра в сингле.** Разделение Character / PlayerController / GameMode
соблюдается строго, изменения состояния идут через методы, которые потом станут Server RPC.
Retrofit репликации на сингловый код в UE — это переписывание геймплея, а сингл при
соблюдении конвенций получается бесплатно как частный случай.

**Ничего не принимается на глаз.** У каждой формулы есть сверка с опубликованной таблицей,
у каждой модели — с источником размеров. Критерий — ~5% от публичных данных.

## Код: `Source/Parabellum/`

### Ballistics — расчётная часть

| Файл | Что считает |
|---|---|
| `PBLBallisticsTypes.h` | все структуры данных: патрон, оружие, материал, слой тела, раскладка боеприпаса, запись каталога. Единицы — СИ |
| `PBLWeaponDataSubsystem` | загрузка `Content/Data/*.csv`, поиск по имени. `pbl.Data.Reload` |
| `PBLBallistics` | внешняя баллистика: точечная масса, драг-функции G1/G7, атмосфера ICAO |
| `PBLPenetration` | проникание в мягкую среду по Понселе, с кувырком FMJ и раскрытием JHP |
| `PBLCycle` | цикл автоматики из импульса выстрела. `VelocityAtTravel()` даёт скорость затвора на заданном ходе — из неё берётся скорость выброса гильзы |
| `PBLRecoil`, `PBLRecoilSettings` | отдача: импульс, подброс, параметры хвата стрелка |

Газоотводная автоматика **не моделируется**: `IsRecoilOperated()` честно отказывается считать
M4A1 и АКМ, пока нет модели газового узла.

### Weapons

| Файл | Что делает |
|---|---|
| `PBLWeapon` | оружие в руках: огонь, перезарядка, прицеливание (`ComputeAimPose`), покачивание от шага (`StepGaitBob`), выброс гильзы, звук |
| `PBLProjectile` | пуля в полёте: траектория, попадание, итог полёта |
| `PBLEjectedCase` | стреляная гильза как физический объект; `PBLAmmo::MeshFor()` находит меш по имени патрона. `pbl.Cases` |
| `PBLBulletDamage` | событие попадания: к точечному урону добавлена энергия, отданная в тканях |

Поза прицеливания выводится из линии прицела, а не подбирается: ось канала ставится
параллельно взгляду, мушка — на `SightHeight` ниже глаза. Расстояние вперёд (`AimForward_cm`)
— единственный свободный параметр.

### Character / Player

`PBLCharacter` — тело и камера; `ApplyMoveSpeed()` — единственное место, где задаются
скорости. `PBLMovementSettings` — параметры тела, движения и покачивания (DeveloperSettings,
секция `[/Script/Parabellum.PBLMovementSettings]` в `DefaultGame.ini`).

`PBLUserSettings` — пользовательские настройки **в сейве, а не в конфиге**. Причина
записана в шапке файла: `UPBLMovementSettings` помечен `DefaultConfig`, то есть лежит в
`DefaultGame.ini` — файле проекта под контролем версий, и `SaveConfig()` на нём молча не
работает. Проектные значения снимаются в `Initialize()` до наложения пользовательских —
иначе «сбросить» нечем: `ReloadConfig()` не восстанавливает то, что задано в коде.

`PBLPlayerController` — клавиши, мышь, HUD, меню. `PBLHUD` — крест и патроны Canvas'ом.

### Range / Targets / Collection / UI

| Файл | Что |
|---|---|
| `PBLWeaponBench` | стенд оружейки: образец висит, вращается мышью, разбирается по шагам, стреляет в замедлении, показывается в разрезе (`C`) |
| `PBLMaterialBlock` | блок испытательного материала: гель, гипсокартон, фанера, доска, сталь |
| `PBLTargetDummy` | реакция на попадание по зоне и отданной энергии |
| `PBLCollection` | что принадлежит игроку, баланс, активный образец. **Все изменения только через `Buy`/`SetActive`** — чтобы при переезде на сервер менялись эти методы, а не интерфейс |
| `SPBLShopPanel` | магазин (F4), витрина из `Catalogue.csv` |
| `SPBLMenuPanel` | меню по Escape: управление и выход |
| `SPBLTuningPanel` | окно испытателя (F2): переопределения параметров оружия на лету |
| `PBLSlateStyle.h` | общий шрифт и кисти. Вынесено не ради красоты: при unity-сборке одноимённые `Font` в разных файлах сталкивались |

### Vision — запарковано

`PBLVisionComponent` + `Shaders/FovealComposite.ush` — фовеальный композит из трёх рендеров,
проекция Панини. **По умолчанию выключено**, играем на обычной камере 112°. Включается
`pbl.Vision 1`. Спека и причины отказа от 180° — в `CLAUDE.md`.

## Данные: `Content/Data/`

| Файл | Содержание |
|---|---|
| `Cartridges.csv` | патрон: масса и диаметр пули, длина, V0 и ствол отсчёта, поправка на длину ствола, драг-модель и BC, поведение в среде (кувырок, раскрытие), гильза |
| `Firearms.csv` | образец: патрон, ствол, темп, масса, магазин, высота прицела, ноль, рассеивание; параметры автоматики (масса затвора, ход, пружина, отпирание, перекос, трение) и окна выброса |
| `Materials.csv` | среда: плотность, прочность, параметры THOR, рикошет |
| `BodyParts.csv`, `BodyLayers.csv` | слои тела: кожа, жир, мышцы, кость |
| `Reference_Gel.csv` | **эталон**: опубликованные глубины в геле 10%, против которых калибруется проникание |
| `Catalogue.csv` | витрина магазина: образец, поколение, цена, год, страна, статус |
| `WeaponParts.csv` | детали, порядок разборки, описания — генерируется из JSON модели |
| `AmmoLayout.csv` | раскладка патронов в магазине и патроннике — генерируется вместе с геометрией |

Последние два **производные**: правятся в скрипте Blender, а не руками.

`Reference/Contours/*.json` — контуры, снятые с фотографий. Тоже данные, из которых строятся
модели, поэтому лежат в репозитории (сами фотографии — нет, они в `Import/`).

## Как проверяется

**Картинка** — `Tools/shot.ps1`: запускает игру headless, ставит игрока, поворачивает камеру,
ждёт и пишет PNG в `Saved/Screenshots`. Открывать редактор не нужно.

```powershell
powershell -File Tools\shot.ps1 -Name aim -Aim 1 -After 12
powershell -File Tools\shot.ps1 -Name cycle -Exec "pbl.Bench.Slow 0.05" -Delayed "pbl.Bench.Fire" -After 20
```

Разрешение по умолчанию 1280×720 совпадает с `DefaultGameUserSettings.ini`: движок пишет
скриншот в разрешении вьюпорта, и расхождение молча даёт не тот кадр.

**Расчёт** — консольные команды. Полный список:

```
pbl.Data.Reload                 перечитать CSV без перезапуска
pbl.Ballistics.Table <патрон>   таблица траектории
pbl.Ballistics.Gel / GelCheck   проникание в гель / сверка с Reference_Gel.csv
pbl.Ballistics.Body / Layer     проникание по слоям тела
pbl.Ballistics.Wound            энергия, отданная тканям
pbl.Ballistics.Recoil           отдача одного выстрела
pbl.Ballistics.Cycle <оружие>   темп из физики отката
pbl.Ballistics.Atmosphere       атмосферные условия

pbl.Bench <оружие>              поставить образец на стенд
pbl.Bench.Stage / Next / Prev   шаги разборки
pbl.Bench.Fire / Slow / Freeze  выстрел, замедление, стоп-кадр цикла
pbl.Bench.Cutaway / Rotate / Hover

pbl.Shop / Shop.Panel / Shop.Buy    магазин
pbl.Collection                      что куплено
pbl.Menu / pbl.Tuning               панели

pbl.Move.WalkSpeed / Move.Reset     скорость ходьбы
pbl.Sens                            чувствительность мыши
pbl.Weapon.V0 / AimPose / AimNudge  параметры оружия на лету
pbl.Range.ClearGel / ClearTrails    убрать следы
pbl.Vision 0/1, pbl.Vision.*        система зрения
```

**Модель** — сверка габаритов в самом скрипте Blender (`dimension check PASSED/FAILED`) и
силуэта с фотографией (`fit_check.py`, IoU). См. [METHOD.md](METHOD.md).

**Сборка**:

```
"C:\Program Files\Epic Games\UE_5.8\Engine\Build\BatchFiles\Build.bat" ParabellumEditor Win64 Development -Project="C:\AI_Claude\Parabellum\Parabellum.uproject" -WaitMutex -FromMsBuild
```

Падает с «Unable to build while Live Coding is active», если открыт редактор или игра.

## Грабли, на которые уже наступили

Собрано здесь, чтобы не наступать второй раз.

- **Bash heredoc режет длинный текст** и съедает обратные слэши: `\b` в пути к Blender
  превратился в символ забоя и сломал четыре `.bat`. Длинные файлы писать файловым
  инструментом, не через heredoc.
- **Python и кириллица в Windows-консоли** — `sys.stdout.reconfigure(encoding='utf-8')`,
  иначе cp1252 роняет печать.
- **FBX приезжает в 1000 раз больше**, если в Blender не задан
  `scene.unit_settings.scale_length = 0.001`.
- **UE дописывает `_001`** к именам импортированных мешей — переименовывать явно в скрипте импорта.
- **BC5 хранит только две компоненты нормали.** Синий канал читается как 0 и после распаковки
  даёт −1: зал чернеет. Z восстанавливать как `sqrt(saturate(1 - dot(rg, rg)))`.
- **`FQuat::FindBetweenNormals`, построенный с нуля, произвольно кренит оружие.** Поза
  прицеливания должна быть поправкой к позе от бедра.
- **Смещение оснастки живёт в костях**: дуло надо брать из мировой трансформации сокета,
  а не из относительной трансформации меша, иначе прицел уезжает.
- **Оружие отключает свой тик, когда успокоится** — живая подстройка параметров не действует,
  пока сеттер не включит тик обратно.
- **Экранный AO Lumen (bent normal) и DFAO** дают тёмную полосу на гранях растянутых кубов:
  выключены в `[ConsoleVariables]`.

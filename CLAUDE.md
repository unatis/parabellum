# Parabellum — контекст проекта

Передача контекста из сессии Claude Cowork (2026-09-09). Этот файл — единственный источник правды по решениям, принятым до начала кода. Обновляй его по мере работы.

## Что делаем

Один уровень-песочница, FPS на **Unreal Engine 5, C++**. Ориентир по геймплею — Counter-Strike (чёткая, отзывчивая стрельба и движение). Ориентир по восприятию — реальное человеческое зрение: широкий обзор (~180°), резкий центр, размытая периферия.

**Не делаем**: бодикам-эстетику (шум, зерно, хроматика, дисторсия, тряска). Картинка должна быть чистой, как в CS.

## Ключевые решения

- **Движок**: Unreal Engine **5.8.2** (выбрано 2026-09-09: последняя стабильная в лаунчере, проект с нуля — мигрировать нечего). Свой движок отвергнут — Lumen/Nanite/физика/сеть/редактор нужны из коробки.
- **Язык**: C++ для геймплея и камер. Python (editor scripting) для генерации greybox-уровня и настройки ассетов. Blueprints/.uasset не редактируются агентом — бинарный формат.
- **Порядок работы**: сначала база на обычной камере (движение, стрельба, уровень), потом «оптика» как отдельный слой поверх. Не начинать с оптики.
- **Уровень**: greybox (примитивы, стены, укрытия, лестницы, спавны), генерируется скриптом. Арт — позже, через Megascans/Fab, не силами агента.
- **Сеть**: архитектура сетевая с самого начала, но играем и тестируем в сингле (listen server, один игрок). Причина: в UE ретрофит репликации на сингловый код — переписывание геймплея; а если сразу соблюдать конвенции (Character/PlayerController/GameMode, replicated properties, Server RPC), сингл получается бесплатно как частный случай. Отложено на потом: lag compensation / server rewind, dedicated server билд, полировка пинга.

## Система зрения (фовеальный рендер) — спека

Проблема: rectilinear-камера не даёт 180° (tan(90°)=∞), а равномерная укладка 180° в 16:9 режет плотность пикселей в центре вдвое против CS.

Решение — **неравномерная проекция + композит из трёх рендеров**:

1. **Центр** — обычный вьюпорт UE, FOV ~100–110°, полное качество (Lumen, TSR, тени). HUD и прицел стандартные.
2. **Бока** — два `SceneCaptureComponent2D` на той же позиции, повёрнуты на ±75–80°, FOV ~70°. Рендер в пониженном разрешении (0.33–0.5×), Lumen минимальный или SSGI, тени ниже. Они всё равно размываются.
3. **Композит** — Post Process Material (HLSL через Custom node) на главной камере:
   - по углу θ от центра взгляда выбирает источник: Scene Color или боковой RT;
   - применяет проекцию `r = f(θ)`: центральные ~60° занимают ~65% ширины экрана (~21 px/градус, как CS на FOV 90), остальные ~120° сжаты в края;
   - Gaussian blur с радиусом, растущим с θ (периферия);
   - опционально: лёгкая десатурация к краям (реализм, мало колбочек на периферии).

Ожидаемая стоимость: ~1.3–1.5× обычного кадра.

### Известные проблемы, закладывать сразу

- **Швы между рендерами**: экспозицию зафиксировать вручную во всех трёх; Lumen screen traces, SSR, SSAO на боковых выключить; bloom — один раз на композите. Размытие периферии должно начинаться внутри зоны центрального рендера, чтобы шов попадал в размытую область.
- **Deprojection**: клик/прицел → луч в мир идёт через кастомную `f⁻¹(r)`, не через стандартный `DeprojectScreenToWorld`. Одна функция, используется везде (стрельба, гранаты, decals).
- **AA/Motion blur**: только внутри каждого рендера, на композите — нет.
- **Lumen в SceneCapture** капризный (5.3+); при проблемах бока — на SSGI.
- **Геймплей**: цель на 40°+ от центра выглядит мелкой — мышечная память CS не переносится. Принято как дизайн-решение.
- Все параметры (FOV центра, углы боков, `f(θ)`, радиус blur) — в настройки, подбираются на глаз по скриншотам.
